# SkillsNexis Internship Week 3

A full-stack Task Manager built on the existing SkillsNexis Week 2 Express and MongoDB backend. The Week 2 backend remains in its own project at `../skillnexis-week2/skillsnexis-week2-backend`; this repository adds the React frontend and the additive image-upload route.

## Features

- Register, login, logout, and JWT session restoration
- Protected React Router dashboard
- User-specific task create, read, update, delete, and completion actions
- All, pending, and completed filters
- Client-side task search
- Axios API client with `Authorization: Bearer <token>`
- Loading states, API errors, and basic form validation
- JPG, JPEG, and PNG image preview and authenticated upload
- Responsive task workspace UI

## Technologies

React 19, Vite, Axios, React Router, Node.js, Express, MongoDB Atlas, Mongoose, JWT, bcryptjs, and Multer.

## Image Storage

The new `POST /api/uploads/image` route accepts a multipart field named `image`. Multer stores files in `uploads/` inside the backend project directory, using a generated filename. Express serves that directory at `/uploads`, so a successful response contains a URL such as `http://localhost:5000/uploads/generated-name.png`. Files are local disk files; they are not stored in MongoDB. The endpoint requires the same JWT Bearer header as tasks.

## API Endpoints

Existing Week 2 endpoints:

- `POST /api/auth/register` with `name`, `email`, `password`
- `POST /api/auth/login` with `email`, `password`
- `GET /api/auth/me`
- `POST /api/tasks`, `GET /api/tasks`, `GET /api/tasks/:id`
- `PUT /api/tasks/:id`, `DELETE /api/tasks/:id`
- `POST /api/notes`, `GET /api/notes`, `GET /api/notes/:id`
- `PUT /api/notes/:id`, `DELETE /api/notes/:id`

Week 3 additive endpoint:

- `POST /api/uploads/image` with multipart field `image`, max 5 MB, JPG/JPEG/PNG only
- `GET /uploads/:filename` serves a successful upload

## How To Test

1. Start the backend and frontend in separate terminals.
2. Register a new account in the frontend.
3. Confirm the dashboard opens and unauthenticated `/` redirects to `/login`.
4. Add a task, edit it, mark it completed, filter it, search it, and delete it.
5. Refresh the page to verify JWT session restoration and user-specific tasks.
6. Select a valid image to verify the local preview, then upload it and verify the returned image is displayed.
7. Use Log out and confirm `/` is protected again.

For a quick API health check from PowerShell:

```powershell
Invoke-WebRequest http://localhost:5000/api/health
```

## Basic Security Checks

- JWT secrets and MongoDB credentials remain backend-only and are never placed in React source.
- Frontend `.env` files are ignored by Git; only `.env.example` is committed.
- Task and upload routes require the existing JWT Bearer middleware.
- Uploads accept only JPG, JPEG, and PNG files and are limited to 5 MB.
- Uploaded filenames are generated by the backend rather than trusted from user input.
- The UI validates required names, email format, password length, task titles, and selected image size/type.

Verified locally: frontend production build passes, frontend lint reports only two advisory React warnings, and new backend upload files pass Node syntax checks. Live MongoDB and browser workflow verification depends on the existing backend `.env` and Atlas availability.
